# Tools

Dotfiles supply platform essentials. Workspace mise.toml supplies project tools,
tasks and non-secret environment. Code repositories may keep their legitimate tool
configuration. Do not add platform or model settings to deployable repositories merely
for agent convenience, including Home Assistant.

Use latest Pi, Node and Rex versions aligned across machines. Do not pin platform
runtime versions. Test upgrades because upstream changes can affect context and
rotation. Record the effective versions when diagnosing a failure or restoring.

Agents may add user-space tools and scripts at workspace scope. Record why they are
needed, verify ARM support and smoke test. Do not change system packages, services,
privileged Docker configuration or host-wide settings without Jan. Propose promotion
of broadly useful tools to dotfiles for review rather than silently modifying the base.

Keep secrets as references to ~/.local/state/ai/projects/<project>.env generated by
ai-sync. Never put credentials in task commands, registry values, notes or committed
configuration. Missing required secrets must fail startup. Only run credential refresh
when intended, never as a smoke test against real user state.

Never print the environment or secret values into a session. Agent environments hold
provider and memory keys, and tool output is stored in session files and backups. Do
not run env, printenv, set or export -p, and do not cat env files, credential caches
or token files. Check a variable by name only, for example env | cut -d= -f1 or
test -n. Report an accidental print to Jan and propose rotating the exposed keys.

Retain shim-first PATH so mise resolves tools for each command's current directory.
The runner loads workspace environment once. Shims cannot update a parent shell's
environment after cd. For an ordinary system command needing nested mise environment,
use mise exec -- <command> from the intended repository.
